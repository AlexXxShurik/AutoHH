# AutoHH

Автоматическое поднятие резюме на [hh.ru](https://hh.ru) / [hh.kz](https://hh.kz). Сервис каждый час проверяет, доступна ли кнопка «Поднять резюме в поиске», и кликает её, как только это возможно.

## Как это работает

1. **Вход в аккаунт** — выполняется через Selenium: на странице входа выбирается вкладка «Почта», вводится email. На странице `localhost` (одна вкладка, обновляется автоматически) по мере шагов запрашиваются: пароль, текст капчи с картинки и 4-значный код подтверждения. При необходимости (капча и т.п.) вход завершается вручную в открытом браузере. Куки сохраняются в файл и переиспользуются при следующих запусках.
2. **Планировщик** — на базе [taskiq](https://taskiq-python.github.io/): при старте задача выполняется сразу, затем — по расписанию cron (по умолчанию каждый час).
3. **Поднятие резюме** — на главной странице ищется кнопка `[data-qa="applicant-index-nba-action_update-resumes"]` и кликается, если она доступна.

> Кнопка «Поднять» отображается только при ширине окна ≥ 1024px, поэтому браузер принудительно открывается в окне 1366×900.

## Установка

Требуется Python 3.11+ и [Poetry](https://python-poetry.org/).

```bash
git clone <url>
cd AutoHH
poetry install
```

## Настройка

Скопируйте шаблон конфигурации и заполните его:

```bash
cp .env.example .env
```

| Переменная       | Описание                                        | По умолчанию        |
| ---------------- | ----------------------------------------------- | ------------------- |
| `BASE_URL`       | Базовый адрес сайта (hh.ru / hh.kz)             | `https://hh.ru`     |
| `HH_EMAIL`       | Email аккаунта для входа                        | —                   |
| `COOKIES_FILE`   | Файл с сохранёнными куки авторизации            | `cookies.pkl`       |
| `CRON`           | Расписание проверки (cron-выражение)            | `0 * * * *`         |
| `TZ`             | Часовой пояс для расписания                     | `Asia/Almaty`       |
| `HEADLESS`       | Режим без окна браузера (`true`/`false`)        | `true`              |

Для первого входа (подтверждение по коду / капча) используйте `HEADLESS=false`.

## Запуск

```bash
poetry run python scheduler.py
```

При старте резюме будет подниматься сразу (если возможно), далее проверка выполняется по расписанию.

## Запуск в Docker

При входе (пароль, капча, код подтверждения) нужен доступ к странице ввода на `localhost`. Из контейнера браузер хоста автоматически открыть нельзя, поэтому сервер ввода запускается **на хосте**, а контейнер обращается к нему через `host.docker.internal`.

Одной командой:

```bash
./run.sh          # первый запуск: интерактивный вход, затем контейнер в фоне
./run.sh stop     # остановить контейнер и сервер ввода
```

При первом запуске сервис ждёт появления куки (`data/cookies.pkl`) — вы входите через страницу `http://localhost:8765` (открывается автоматически). Как только куки созданы, скрипт сам останавливает интерактивный режим и запускает контейнер в фоне (`docker compose up -d`). Логи первого запуска пишутся в `compose_login.log`, консоль не забивается.

Сервер ввода держится в фоне (`input_server.log`) — он нужен и для повторного входа при истёкших куки. Если вход перестал работать, удалите `data/cookies.pkl` и запустите `./run.sh` снова.

## Структура проекта

```
AutoHH/
├── scheduler.py            # Точка входа: запуск задачи и планировщика
├── app/
│   ├── config.py           # Настройки из .env
│   ├── driver.py           # Создание Selenium WebDriver
│   ├── auth.py             # Авторизация (email + пароль + капча + OTP-код), работа с куки
│   ├── input_server.py     # Сервер страницы ввода (localhost) — на хосте или в процессе
│   ├── input_client.py     # Клиент сервера ввода (для Docker через host.docker.internal)
│   ├── resume.py           # Логика поднятия резюме
│   └── tasks.py            # taskiq-задачи, broker и scheduler
├── docker-compose.yml      # Запуск в Docker
├── Dockerfile
├── .env.example            # Шаблон конфигурации
└── pyproject.toml          # Зависимости (Poetry)
```
